# Changelog

All notable changes to Tunnel-Lab are documented here.
Versioning: MAJOR.MINOR.PATCH

## 0.4.1
- Added install.sh: automated installer for Ubuntu 24.04.
- Installer handles PEP 668 (externally-managed-environment) via venv fallback.
- Installer checks textual version and uses venv if system textual < 0.60.
- Added run.sh helper generated by installer.
- Fixed advisor.py.py -> advisor.py filename issue.
- Added ARCHITECTURE.md and README.md.

## 0.4.0
- Bidirectional test: DIRECT (A->B) and REVERSE (B->A) as separate phases.
- Three traffic layers per direction: ICMP, TCP, UDP.
- Tiny payload (64 bytes, one shot) with explicit ACK.
- Per-side, per-tunnel result report.
- New failure types: DIRECT_TCP_FAILED, REVERSE_UDP_FAILED, etc.
- New core/payload.py with TCP and UDP sender/receiver.
- Agent now handles RECV_TCP, RECV_UDP, SEND_TCP, SEND_UDP.

## 0.3.0
- Two-server architecture: Server A (controller) + Server B (agent).
- Control Channel: pure-Python TCP + JSON between A and B.
- Agent on B executes whitelisted commands.
- SSH only used for initial agent deployment on B.
- Advisor module: turns raw results into human-readable suggestions.
- Tunnel modules now expose commands_for_a() and commands_for_b().
- Live A<->B message log in UI.

## 0.2.0
- UI rewritten with Textual.
- Arrow-key navigation in all menus and lists.

## 0.1.0
- Initial project skeleton.
- Core: config, logger, protocol, state, context, allocator, executor.
- Tunnels: gre, ipip, gretap, sit, vxlan, wireguard, ssh_tun.

## 0.4.2
- ConfigScreen redesigned: two columns, compact, with hints.
- Added core/netinfo.py: local public IP detection (no external service).
- "Detect public IP" button for Server A (works on filtered servers).
- Ctrl+S save, Ctrl+D detect A, Ctrl+E detect B.
- CSS: tighter spacing, Input height reduced, hints docked.

## 0.4.3

- Password input is paste-friendly (no longer masked).
- Detect public IP fixed: uses route + global-scope addr scan.
- Added list_global_ips() helper.
- ssh_setup: auth auto-detected from key_path presence.
- config.yaml cleaned from auth/key_path.

## 0.4.4
- ConfigScreen: add "Edit config in nano" (Ctrl+E) as workaround for

## 0.4.5

- Solves paste issues: all input goes through whiptail's inputbox.

## 0.4.6

## 0.4.7

  it via SFTP, and extracts on Server B. Ensures the exact same code

- Automatically installs python3 on B if missing.

## 0.4.9

## 0.8.3
- SIT tunnel now uses IPv6 (6in4) properly:
  - tunnels/base.py adds `family = "ipv4"` (default).
  - tunnels/sit.py sets family="ipv6", uses fd00:6in4::1/2.
  - orchestrator detects family and runs IPv6-specific ICMP/TCP/UDP tests.
  - core/payload.py adds tcp6_receiver, udp6_receiver, tcp6_send, udp6_send.
  - agents/agent.py handles RECV_TCP6, RECV_UDP6, SEND_TCP6, SEND_UDP6.

## 0.8.4
- Fix: orchestrator IPv6 helper methods (_icmp6_*, _tcp6_*, _udp6_*)
  were not applied in 0.8.3. This release makes sure they exist
  and _run_phase uses the IPv6 branch when mod.family == "ipv6".

## 0.8.5
- ICMP checks relaxed: try ping -c 3 -W 5, ping6, ping -c 1 -W 3.
  First IPv6 packet on SIT often triggers neighbor discovery and
  the old "2 packets / 2s" test could fail even when the tunnel
  was working (as seen via tcpdump).

## 0.8.6
- SSH_TUN now opens a real ssh -w 0:0 session on A to bridge the two
  tun devices (was previously a plain tun with no link).
- orchestrator._ssh_tun_link() runs on each phase.
- Requires sshpass on A (installed automatically if missing).
- Server B: PermitTunnel yes and PermitRootLogin yes are enabled.

## 0.8.7
- SSH_TUN rewritten: uses `ssh -w 0:0` to create tun0 on both sides,
  then assigns IPs to tun0 (not to a separate tuntap device).
- Fixes "Device or resource busy" when tun0 was already claimed.
- orchestrator._ssh_tun_link() now assigns IPs on both sides after
  the SSH session is up.
- interface_name for ssh_tun is now "tun0".

- DIRECT : A opens ssh -L 19999 -> B:19998, sends payload on 127.0.0.1:19999.
- REVERSE: B opens ssh -L 19998 -> A:19999, A listens and receives.
- No more setsid, no more PID files, no more SOCKS conflicts.

## 9.0.2

- menu returns directly to the main menu.

## 9.0.3
- SSH_TUN switched from SOCKS5 to ssh -L local port forwarding.
- DIRECT : A: ssh -L 19999 -> B:19998, payload 127.0.0.1:19999.
- REVERSE: B: ssh -L 19998 -> A:19999, payload 127.0.0.1:19998.

## 9.0.4
- SSH_TUN now uses real nc listener + ssh -L, verified end-to-end.
- DIRECT : B: nc listens on 19998, A: ssh -L 19999->B:19998, A sends,
           B's captured file must contain the payload.
- REVERSE: A: nc listens on 19999, B: ssh -L 19998->A:19999, B sends,
           A's captured file must contain the payload.
- No more RECV_TCP deadlock on the control channel.

## 9.2.0
- SSH_TUN final: uses nc listener + ssh -L, end-to-end verification.
- DIRECT  : B listens on 19998, A: ssh -L 19999->B:19998, payload verified.
- REVERSE : A listens on 19999, B: ssh -L 19998->A:19999, payload verified.
- Removed all SOCKS5 code paths.
- Cleaned up: core/socks.py and tunnels/socks5.py removed.
